# Testing

> Purpose: the test layers that exist, the exact commands, what each needs to run, and how CI gates a merge.
> Last verified: 2026-09-20 (`package.json`, `server/package.json`, `client/package.json`, `client/jest.config.js`, `playwright.config.js`, `.github/workflows/ci.yml`).

## 1. Layers

| Layer | Location | Runner | Needs | Add yours in |
|---|---|---|---|---|
| Server unit | `server/test/unit/{@system,@custom}` | Jest 29 (Babel via `server/.babelrc`) | nothing (mock `lib/@system/PostgreSQL`) | `server/test/unit/@custom/` |
| Server API | `server/test/api/{@system,@custom}` | Jest + supertest against `src/app.js` | nothing for most; some suites mock repos | `server/test/api/@custom/` |
| Server integration | `server/test/integration/*.integration.test.js` | Jest | `DATABASE_URL` to a real Postgres (skipped otherwise) | same folder |
| Server smoke | `server/test/smoke/post-deploy.test.js` | Jest, plain `fetch` | `BASE_URL` of a deployed app (skipped otherwise) | same folder |
| Client unit/component | `client/src/test/{@system,@custom}` | Jest 29 + jsdom + Testing Library (`client/jest.config.js`) | nothing; CSS/images/lucide mocked | `client/src/test/@custom/` |
| E2E | `e2e/{@system,@custom}/*.spec.js` | Playwright (`playwright.config.js`) | running app at `BASE_URL` (default `http://localhost:3000`) and browsers (`npx playwright install`) | `e2e/@custom/` |

Contract tests worth knowing about: `server/test/api/@system/route-override.test.js` (custom-first merge), `server/test/api/@system/middleware-order.test.js`, `client/src/test/@system/{config-resolver,content-override,brand-paint,brand-preload}.test.*` (override chain and brand pre-paint).

## 2. Commands

From the repo root unless a `cd` is shown.

```bash
# Lint
(cd client && npm run lint)

# Client tests
(cd client && npm test)                     # jest --maxWorkers=2
(cd client && npm run test:watch)
(cd client && npm run test:coverage)

# Server tests
(cd server && npm test)                     # everything under server/test (integration/smoke self-skip without env)
(cd server && npm run test:unit)            # jest --testPathIgnorePatterns=integration smoke
(cd server && npm run test:integration)     # needs DATABASE_URL
(cd server && BASE_URL=https://<app-url> npm run test:smoke)

# Root shortcuts
npm run test:unit                           # cd server && npm test -- --testPathPattern=test/unit
npm run test:api                            # cd server && npm test -- --testPathPattern=test/api
npm run test:client                         # cd client && npm run test
npm test                                    # test:unit + test:api + test:e2e (e2e needs a running app)

# Build (prebuild.js runs first via the npm hook)
npm run build

# E2E
npx playwright test                         # all projects: chromium, firefox, webkit, mobile-chrome
npx playwright test --project=chromium e2e/@custom
npm run test:e2e:ui | npm run test:e2e:headed | npm run test:e2e:report
BASE_URL=https://<preview-url> npx playwright test

# Type check (tsc --noEmit in both workspaces; JS project, types are advisory)
npm run typecheck
```

Env for API tests that hit auth: `NODE_ENV=test` disables rate limiting; JWT keys come from `server/.env` (`npm run generate-keys`) or are auto-generated by the test setup where the suite does so. `TEST_API_KEY` + `X-Test-Key` header bypasses rate limits in deployed environments.

## 3. Writing tests

Server API test skeleton (mirrors `server/test/api/@custom/dashboard.test.js`):

```js
const request = require('supertest')
jest.mock('../../../src/db/repos/@custom/ProjectRepo', () => ({ listForUser: jest.fn().mockResolvedValue([{ id: 1, name: 'A' }]) }))
const app = require('../../../src/app')

describe('GET /api/projects', () => {
  it('requires auth', async () => {
    const res = await request(app).get('/api/projects')
    expect(res.status).toBe(401)
  })
})
```

Client component test skeleton (see `client/src/test/@custom/LoadingSpinner.test.jsx`):

```jsx
import { render, screen } from '@testing-library/react'
import { StatusPill } from '@/app/components/@custom/StatusPill'
test('renders children', () => {
  render(<StatusPill ok>Live</StatusPill>)
  expect(screen.getByText('Live')).toBeInTheDocument()
})
```

Playwright skeleton (see `e2e/@system/01-public-pages.spec.js`; fixtures in `e2e/fixtures/index.js`):

```js
import { test, expect } from '@playwright/test'
test('projects page needs login', async ({ page }) => {
  await page.goto('/app/projects')
  await expect(page).toHaveURL(/\/auth/)
})
```

Rules: tests for `@custom` code live in `@custom` test folders; never edit `@system` tests in a product repo (they are synced); mock external services (Stripe, email, S3); no live-network calls in unit/api suites.

## 4. How CI gates

`.github/workflows/ci.yml` runs on every push and pull request to `main` (10 min timeout, Node 22, `npm ci --ignore-scripts` in root, client, server):

1. Lint: `cd client && npm run lint`
2. Client tests: `cd client && npm test`
3. Server tests: `cd server && npm test -- --forceExit --ci` with `NODE_ENV=test`
4. Build: `npm run build` (runs `scripts/prebuild.js` then the production Webpack build and `client/scripts/verify-build.mjs`)
5. Docker smoke: `docker build` of the root `Dockerfile` and a `GET /api/health` against the container

All five steps are blocking. `.github/workflows/deploy.yml` runs only after CI succeeds on `main`. `buildspec-ci.yml` is the AWS CodeBuild equivalent for repos wired to CodeBuild.

Current state (2026-09-20): the committed `ci.yml` still wraps lint and server tests in `|| echo ...` (non-blocking), has no client-test step and no Docker smoke step, and `deploy.yml` has no dependency on CI. The pipeline agent is landing the blocking version described above; until it merges, run the checklist in `CLAUDE.md` locally before pushing.

E2E is not part of CI; run it locally or against the preview URL posted by `.github/workflows/preview.yml` on pull requests.

## 5. Coverage and flakiness

- `cd client && npm run test:coverage` writes `client/coverage/`.
- Playwright retries twice on CI (`retries: process.env.CI ? 2 : 0`), records traces on first retry and screenshots on failure; reports in `playwright-report/`.
- If a server suite hangs, run with `--forceExit` (pool handles); if it leaks, make sure repos are mocked or `disconnectPool()` is called once in a global teardown, not per file.
