# Security checklist

> Purpose: the checkbox version of `docs/SECURITY.md`, for pull-request review and pre-release sign-off. Each line names the file that implements or verifies it.
> Last verified: 2026-09-20.

## Every pull request

- [ ] Every new POST/PUT/PATCH/DELETE route has `validate({ body|query|params })` with a zod schema (`server/src/lib/@system/Validation`).
- [ ] Every new route that reads or writes user data has `requireAuth` (or `authenticate`) and, where relevant, `requireAdmin` / `requireTenantRole` (`server/src/middleware/@system/auth.js`, `server/src/lib/@custom/tenantContext.js`).
- [ ] SQL uses pg-promise `$1` placeholders only; dynamic identifiers are whitelisted (compare `server/src/db/repos/@system/UserRepo.js`).
- [ ] Queries on tenant-owned tables include `tenant_id = $n`.
- [ ] Schema changes ship an idempotent migration in `server/src/db/migrations/@custom/`.
- [ ] Abusable endpoints (email, money, unauthenticated) have a `createLimiter` (`server/src/lib/@system/RateLimit`).
- [ ] Errors go through `next(err)` / typed `AppError`; no stack traces or raw provider errors in responses (`server/src/app.js`).
- [ ] No secrets, `.env`, or `server/.keys/` in the diff; new env vars added to `server/.env.example` and, if required, to `REQUIRED_VARS` in `server/src/lib/@custom/Env/index.js`.
- [ ] New third-party origins added to `brand.json` `securityHeaders.contentSecurityPolicy` instead of loosening CSP.
- [ ] Client mutations use `lib/@system/api.js` (cookies + CSRF header), not bare `fetch`.
- [ ] User-supplied HTML is sanitised (`sanitize-html`) before storage or rendering.
- [ ] Tests added for authorization paths (401/403) in `server/test/api/@custom/`.

## Before a production deploy

- [ ] `NODE_ENV=production`; `SKIP_CSRF` and `GRAPHQL_INTROSPECTION` unset.
- [ ] `APP_URL` is the public origin; `CORS_ORIGINS` contains only real origins; no `RAILWAY_*` leftovers.
- [ ] `CSRF_SECRET` (32+ chars), `JWT_PRIVATE_KEY[_FILE]`, `JWT_PUBLIC_KEY[_FILE]`, `ENCRYPT_KEY`, `ENCRYPT_IV` set as App Runner secrets (not auto-generated by `start.sh`).
- [ ] `DATABASE_URL` uses SSL where the provider supports it; `DB_SSL_REJECT_UNAUTHORIZED` left `true` unless a CA is provided.
- [ ] `REDIS_URL` set (rate-limit store, logout blacklist, lockout counters).
- [ ] `STRIPE_WEBHOOK_SECRET` matches the dashboard endpoint for `/api/stripe/webhook`.
- [ ] `SENTRY_DSN` set; CloudWatch log retention configured.
- [ ] `npm audit --omit=dev` in `server/` and `client/` has no unaccepted high/critical findings.
- [ ] `GET /api/health` on the deployed URL shows `status: ok`, `db: connected`, `auth: ok`.
- [ ] Security headers verified on the deployed URL: `curl -sI https://<app-url>/ | grep -iE 'content-security-policy|strict-transport|x-frame|permissions-policy'`.

## Error handling, request correlation and tenant RLS (server, 2026-09-20)

- **Files:** `server/src/lib/@system/Middleware/errorHandler.js`, `requestId.js`
- ✅ Every response carries `X-Request-Id` (incoming edge id reused when well-formed)
- ✅ Error JSON is `{ message, code?, requestId }`; in production every 5xx uses a
  generic message — driver/stack/path text is logged, never returned
- ✅ 4xx messages pass through (they are user-authored); driver codes (`23505`) never
  forwarded, only `UPPER_SNAKE` application codes
- **Tests:** `server/test/unit/@system/error-handler.test.js`, `request-id.test.js`

### 4c. Tenant Isolation (Postgres Row-Level Security)
- **Migration:** `server/src/db/migrations/@custom/003_tenant_rls.js` (idempotent;
  `ENABLE` + `FORCE ROW LEVEL SECURITY`, policy on
  `current_setting('app.current_tenant_id', true)`)
- **Helper:** `withTenant(tenantId, fn)` / `req.withTenant(fn)` in
  `server/src/lib/@custom/tenantContext.js` — transaction + `set_config(..., true)`
  (SET LOCAL semantics). Without the setting, RLS returns/permits **no** rows.
- **Example:** `server/src/api/@custom/todos-example.js` + `db/repos/@custom/TodoRepo.js`
- ⚠️ Do not run the app as a Postgres superuser (superusers bypass RLS).
- **Tests:** `server/test/unit/@custom/tenant-context.test.js`,
  `todos-example.route.test.js`, `003_tenant_rls.test.js`

## ⚠️ Known Gaps (documented, not yet fixed)

- `sameSite=lax` (not `strict`) on auth cookies — needed for OAuth redirects; CSRF
  double-submit covers state-changing requests.
- `/api/sessions/refresh` and `/api/auth/refresh` are CSRF-exempt by design
  (silent background refresh); mitigated by rotation + reuse detection.
- `Helpers/auth.js` failure lockout store is per-process (not Redis) — multi-instance
  deployments get per-instance thresholds.
- `GET /api/users/unsubscribe?email=` in `communications` has no token check —
  anyone can unsubscribe any address.
- `POST /api/storage/upload-url`: `folder` is now regex-restricted at the route, but
  `StorageAdapter.createUploadUrl({ key })` still trusts the key it receives.
- `POST /api/storage/process-image` ownership check only inspects the newest file
  (`getUserFiles(..., { limit: 1 })`) — other owned files 404.
- `TEST_API_KEY` shorter than 32 chars is only warned about, not rejected.
- `server/scripts/drop-schema-migrations.js` still exists as a manual operator tool
  (documented in `docs/MIGRATIONS.md`); it is no longer invoked automatically.
